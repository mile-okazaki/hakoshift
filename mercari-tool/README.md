# mercari-tool — メルカリ出品支援エンジン

リサーチ → 価格設定 → 画像加工 → 文章生成 → 出品ドラフト出力 → コメント返信 →
売上管理 → スプレッドシート反映 までを1本のコマンドラインで扱うツールです。

---

## ⚠️ はじめに読んでください（自動出品について）

**このツールは「自動出品Bot」ではありません。**

メルカリには公開の出品APIが無く、**ボットやスクリプトによる自動出品・自動操作・
スクレイピングは利用規約（禁止事項）で明確に禁止**されています。実装すれば
アカウント停止・売上金没収のリスクがあり、それは作る意味がありません。

そこで本ツールは、**出品ボタンを押す直前まで全部を自動でやる**設計にしています。

| 工程 | 自動化 |
|---|---|
| 相場リサーチ・統計 | ✅ 全自動 |
| 価格設定・利益計算 | ✅ 全自動 |
| 写真の加工・背景処理 | ✅ 全自動 |
| サムネイル作成 | ✅ 全自動 |
| タイトル・キャッチコピー | ✅ 全自動（APIキー無しでも動作） |
| 商品説明文 | ✅ 全自動（APIキー無しでも動作） |
| コメント返信文の作成 | ✅ 全自動（送信は手動 or 半自動） |
| 仕入れ先の評価・選定 | ✅ 全自動 |
| 売上・純利益の集計 | ✅ 全自動 |
| スプレッドシート反映 | ✅ 全自動 |
| **メルカリへの投稿操作** | ❌ **利用者が行う**（規約遵守のため） |

`draft` コマンドが「タイトル／価格／説明文／画像」を貼るだけの状態で出力するので、
実作業は**アプリでコピペして出品ボタンを押すだけ**になります。
1商品あたり15〜30分かかっていた作業が、数分で終わります。

## セットアップ

```bash
cd mercari-tool

# 1. 仮想環境と依存関係
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. 初期化（データディレクトリと .env を作成）
python -m mercari_tool init

# 3. （任意）.env に ANTHROPIC_API_KEY を設定
#    未設定でも全工程が動きます。設定するとタイトル・説明文の表現が
#    ルールベースからClaude生成に切り替わります。
```

以降 `python -m mercari_tool ...` で実行します。
`pip install -e .` すると `mercari-tool ...` という短いコマンドが使えます。

### 必要なもの

| 用途 | 必要なもの |
|---|---|
| **全機能（出品の手前まで一通り）** | **Python 3.10+ のみ** |
| 文章の質を上げたい場合のみ | Claude API キー（[取得](https://console.anthropic.com/)、任意） |
| スプレッドシート連携 | Google サービスアカウントのJSONキー |
| サムネイルの日本語表示 | 日本語フォント（多くの環境に既存。無ければ `MERCARI_FONT_PATH` で指定） |

## 5分ではじめる

```bash
# ① 商品を登録
python -m mercari_tool product add \
  --sku NK-AM90-27 \
  --name "ナイキ エアマックス 90 27cm" \
  --category "メンズ/靴/スニーカー" --brand NIKE \
  --condition no_scratch --cost 4200 --shipping size80 \
  --keywords "ナイキ,エアマックス,27cm" \
  --points "定番のホワイト|箱付き" \
  --defects "アウトソールに薄い汚れ"

# ② 相場を書き写す（メルカリで同じ商品を検索して、売れている値段を並べる）
python -m mercari_tool research add --sku NK-AM90-27 --prices 9800,11500,8900,10200

# ③ 写真をフォルダに入れる（ファイル名順が掲載順になる）
#    photos/01_正面.jpg  02_背面.jpg  03_タグ.jpg ...

# ④ 出品ドラフトを一括生成
python -m mercari_tool draft NK-AM90-27 --photos-dir photos --whiten
```

`data/output/NK-AM90-27/` に以下が出力されます。

```
listing.txt              ← 出品画面にコピペする用（項目ごとに区切り済み）
draft.json               ← 全データ（相場・価格根拠・生成物）
images/
  NK-AM90-27_01.jpg      ← 加工済み写真
  NK-AM90-27_02.jpg
  NK-AM90-27_thumbnail.jpg  ← 1枚目に使うサムネイル
```

## 機能ごとの使い方

### 1. リサーチ（相場調査）

```bash
python -m mercari_tool research "ナイキ エアマックス 90 27cm"
```

```
■ 相場リサーチ: ナイキ エアマックス 90 27cm
  サンプル       : 10 件（売却済み 8 / 出品中 2）
  売却率         : 80%
  中央値         : 10,000 円
  価格帯(25-75%) : 9,350 〜 10,750 円
  平均売却日数   : 9.0 日
  価格トレンド   : → 1.00（直近/過去）
  状態別中央値   : 目立った傷や汚れなし=10,000円, 未使用に近い=12,150円
  頻出キーワード : 27cm / エアマックス / ナイキ
  ⚠ 外れ値 1 件を統計から除外しました。
```

やっていること:

- **統計は「売れた出品」だけで計算**します。出品中の価格は売り手の希望額であって
  成約価格ではないため、混ぜると相場が実態より高く出ます。
- **外れ値を自動除去**します（IQRの1.5倍超）。桁を間違えた出品1件で中央値が壊れないように。
- **状態別の中央値**を出します。「美品」と「傷あり」が混ざった中央値は使いものにならないためです。
- **売れているタイトルの頻出語**を抽出し、タイトル生成に渡します。

#### 相場データの用意（いちばん手軽な方法）

メルカリの検索結果を自動取得することは規約上できないため、**人が見た値段を
書き写す**のが前提です。ただしCSVを手作りする必要はありません。
`research add` に打ち込めば、集計まで一気に通ります。

```bash
# ① 値段を並べるだけ（いちばん速い）
python -m mercari_tool research add --sku NK-AM90-27 --prices 9800,11500,8900,10200

# ② 検索結果を見ながら1行ずつ貼り付ける（Ctrl-D で確定）
python -m mercari_tool research add --sku NK-AM90-27
ナイキ エアマックス90 27cm 白 9800円 売切
エアマックス 90 27cm 美品 11500 SOLD
出品中 16800円 27cm
^D

# ③ メモ帳に溜めたものをまとめて読ませる
python -m mercari_tool research add "ナイキ エアマックス 90 27cm" --file prices.txt
```

```
■ 相場データを更新: 「ナイキ エアマックス 90 27cm」
  追加 3件 / 重複スキップ 1件 / 合計 10件
  保存先: data/comps/ナイキ-エアマックス-90-27cm.json
（続けて集計結果が表示されます）
```

行の読み方:

| 書いたもの | 読まれ方 |
|---|---|
| `9800` / `9,800円` | 価格 |
| `エアマックス 90 27cm 11500` | 「円」が無ければ**行内で最大の数値**が価格（型番90やサイズ27と取り違えない） |
| `売切` `売り切れ` `SOLD` | 売却済み |
| `出品中` `販売中` | 出品中（成約価格の統計に入れない） |
| `美品` `新品未使用` `未使用に近い` | 状態 |
| `2026-08-01` `8月1日` | 売却日 |
| `# メモ` / 空行 | 無視 |

- **同じ内容の行は二重に登録されません**。何度打っても相場が水増しされません。
- `--sku` を付けると「ブランド + 商品名 + サイズ」を検索語として保存するので、
  `draft` がそのまま拾います。検索語を自分で決めたい場合は文字列で渡します。
- `--condition no_scratch` で全件に状態をまとめて付けられます。
- `--active` を付けると全件を「出品中」として記録します。
- 入れ直したいときは `--replace`。

#### CSVで用意する場合

Excelで作った表をそのまま置くこともできます。`data/comps/` に、検索語を
ファイル名にして保存します。

`data/comps/ナイキ-エアマックス-90-27cm.csv`:

```csv
商品名,価格,売却,状態,売却日,出品日
ナイキ エアマックス90 27cm 白,9800,売却済み,目立った傷や汚れなし,2026-07-02,2026-06-28
ナイキ エアマックス90 27cm 黒,11500,売却済み,未使用に近い,2026-07-05,2026-06-25
ナイキ エアマックス90 27cm 美品,13500,,未使用に近い,,2026-08-05
```

- 列は `price` 以外すべて省略可。英語ヘッダー（`title,price,sold,...`）も使えます。
- **`売却` 列が空欄の行は「出品中」**として扱われます（成約価格の統計には入りません）。
- `売却` 列そのものが無いCSVは、全行を売却実績とみなします。

JSONを返す独自エンドポイントから取得することもできます（`.env` の
`MERCARI_ALLOW_HTTP_RESEARCH=1` と `MERCARI_RESEARCH_ENDPOINT`）。
**取得先の利用規約・robots.txt の遵守は利用者の責任**です。

### 2. 価格設定

```bash
python -m mercari_tool price suggest NK-AM90-27
```

```
  【早く売る】 8,980 円   … 相場の下限寄り。回転を優先。
    → 純利益 2,982 円（利益率 33.2% / ROI 71.0%）
  【バランス】 9,980 円   … 相場の中央値。もっとも成約しやすい。
    → 純利益 3,882 円（利益率 38.9% / ROI 92.4%）
★ 【利益重視】 11,180 円  … 相場の上限寄り。
    → 純利益 4,962 円（利益率 44.4% / ROI 118.1%）

  損益分岐価格 : 5,667 円（これ未満は赤字）
  値下げ下限   : 6,480 円（利益率 12% を確保）
```

- 販売手数料10%・送料・梱包資材費・振込手数料・仕入れ値を**すべて引いた純利益**で計算します。
- ★ は推奨案。**売却率が高い市場なら利益重視、低いなら回転重視**を自動で選びます。
- どの案も**損益分岐を下回りません**。相場が仕入れ値より安い場合は警告します。
- 価格は `...980` のような買われやすい端数に自動調整されます。

**仕入れ前の逆算**もできます。

```bash
python -m mercari_tool price maxcost --price 10000 --shipping size80 --margin 0.3
#  → 仕入れは 5,100 円までなら目標を達成できます。
```

**値下げ交渉の判定**:

```bash
python -m mercari_tool price offer NK-AM90-27 6000
#  判定: 🔄 逆提案する
#  理由: 利益は残りますが利益率 5.0% が下限 12% 未満です。6,480円で逆提案しましょう。
```

### 3. 写真の受け渡しと加工

写真はフォルダごと渡せます。**ファイル名の昇順がそのまま掲載順**になるので、
撮影順に番号を付けておけばそのまま使えます。

```
photos/
  01_正面.jpg      ← 1枚目。サムネイルはこの写真から作られる
  02_背面.jpg
  03_タグ・型番.jpg
  04_ソール.jpg
  05_傷の箇所.jpg
```

```bash
python -m mercari_tool draft NK-AM90-27 --photos-dir photos --whiten
# 個別指定もできます
python -m mercari_tool draft NK-AM90-27 --photos a.jpg b.jpg
```

対応形式: jpg / jpeg / png / webp / heic / heif / bmp / tif

枚数のチェックも入っています。

- **10枚を超える** → 先頭10枚を使い、警告
- **4枚未満** → 警告（正面・背面・タグ・傷の箇所は最低限あると問い合わせが減ります）
- **0枚** → 警告（メルカリは画像1枚以上が必須）

### 4. 画像の加工・修正

```bash
python -m mercari_tool image process photo1.jpg photo2.jpg --whiten --out edited -v
```

```
✔ edited/photo1_edited.jpg
    - EXIFの向きを補正
    - 余白を切り詰め (1600, 2100) → (777, 637)
    - ホワイトバランス補正 (上限×1.25)
    - 明るさ自動補正 ×0.92 (平均輝度 183 → 目標 168)
    - 自動レベル補正 (cutoff=0.4)
    - 背景を白飛ばし (許容差=42)
    - アンシャープマスク ×1.0
    - 正方形化 777x637 → 777x777
```

- **色を変えない加工**を優先しています。レベル補正は輝度基準（`preserve_tone`）で行い、
  ホワイトバランスにも補正上限を設けています。グレーの商品が青や緑に転ぶと
  「写真と色が違う」というクレームに直結するためです。
- `--whiten` は四隅から連続した均一な背景を白飛ばしします（壁・机など）。
  柄物の背景や被写体が画面端に接している写真では期待通りにならないことがあります。
- **拡大はしません**（画質が落ちるため）。`--size` は縮小の上限です。

背景を透過PNGにしたい場合は Python から:

```python
from mercari_tool.images import ImagePipeline
ImagePipeline.open("photo.jpg").remove_background().save("out.png")
```

### 5. サムネイル作成

```bash
python -m mercari_tool image thumb photo1.jpg \
  --top "送料無料　11,180円" --corner "美品" --bottom "国内正規品" --palette red
```

1080×1080の正方形で、商品写真＋帯＋バッジを合成します。
背景は元写真をぼかして敷くので、縦長・横長写真でも白帯が目立ちません。

`draft` から生成する場合、載せる文言は**事実として言えることだけ**を
自動で選びます（送料負担・商品状態・登録済みの訴求ポイント）。
「激安」「大人気」のような根拠のない煽り文句は入れません。

### 6. タイトル・キャッチコピー・説明文

`draft` コマンドで自動生成されます。**APIキーの有無で経路が変わります。**

| | APIキー無し（既定） | APIキーあり |
|---|---|---|
| タイトル | 商品情報と相場から**5案を組み立て** | Claudeが5案を生成 |
| キャッチコピー | 登録内容から3案 | Claudeが3案 |
| 説明文 | 定型構成で組み立て | Claudeが文章として執筆 |
| 上限・整合チェック | ✅ 同じ | ✅ 同じ |

APIキー無しの場合、タイトルは次のように組み立てられます。

```
ナイキ エアマックス 90 27cm 美品   ← ブランド→商品名→サイズ→状態
ナイキ エアマックス 90 スニーカー ホワイト  ← 相場の頻出語を前寄りに
美品 ナイキ エアマックス 90 27cm  ← 状態で絞り込む買い手向け
エアマックス 90 27cm             ← 最短形
```

- 40文字を超える場合は、**重要度の低い語から自動で落として**収めます
  （商品名だけは必ず残ります）。
- 相場リサーチで見つけた頻出語は、**商品側の登録内容に裏付けがある語だけ**を使います。
  「売れているタイトルに多いから」というだけで、この商品に当てはまらない語は入れません。
- 「美品」「新品未使用」は、**申告した難点と矛盾する場合は付けません**
  （新品なのに傷を申告している、難点が2つ以上あるのに美品、など）。
- タイトルは**5案**生成し、40文字以内に収まっているものを先頭に並べます。
  超過している案には警告が付きます。
- 説明文は【商品の詳細】【状態】【発送について】【ご購入前に】の構成で、
  1000文字以内に収めます。
- **登録した難点（`--defects`）が説明文に反映されていないと警告**します。
  傷を隠した出品は評価を落とすので、コード側でチェックしています。
- 「正規品保証」「ノークレームノーリターン」など、**トラブルになりやすい表現**を
  検出して警告します。
- 相場リサーチで見つけた頻出キーワードを渡しますが、
  「この商品に事実として当てはまる語だけを使うこと」と指示しています。

### 7. コメント返信

```bash
python -m mercari_tool comment NK-AM90-27 --text "4500円になりませんか？"
```

```
受信コメント: 4500円になりませんか？
意図        : 値下げ交渉
提示額      : 4,500 円
価格判定    : decline — 損益分岐 5,667円を下回るため赤字になります。
判定        : ⚠ 送信前に確認してください

コメントありがとうございます。
申し訳ございませんが、ご提示の金額へのお値下げは難しい状況です。
6,480円が限界となりますので、ご検討いただけますと幸いです。
```

**設計上の要点: 金額の判断をAIに任せていません。**

1. ルールでコメントの意図を分類（値下げ / 在庫 / 発送 / 状態 / 専用 / クレーム）
2. 値下げなら金額を抽出し、**価格エンジンが受諾可否を決定**
3. その結論をClaudeに渡し、**文章化だけ**をさせる

こうしないと、モデルが気を利かせて赤字価格を約束してしまう事故が起きます。

- **値下げ交渉とクレームは、必ず人の確認が必要**（`auto_send_ok: false`）になります。
- 在庫確認・発送・状態の質問は `auto_send_ok: true` です。
- APIキーが無い／APIが落ちている場合は、テンプレートに自動フォールバックします。

複数コメントの一括処理:

```bash
python -m mercari_tool comment NK-AM90-27 --file comments.txt --json
```

### 8. 仕入れ先の選定・調査

```bash
python -m mercari_tool supplier add --id sup_a --name "国内リサイクル卸A" \
  --channel "ネット卸" --unit-cost 4200 --lead-time 3 --min-qty 1 \
  --order-shipping 800 --defect-rate 0.02 --reliability 4.5 --order-count 24

python -m mercari_tool sourcing rank --sku NK-AM90-27
```

```
1. 実店舗せどり  [スコア 79/100]
   単価 / 実質原価: 5,200円 / 5,200円（送料按分・不良率込み）
   1個あたり利益  : 2,900円（利益率 29.0% / ROI 55.8%）
   1回の発注      : 5,200円投下 → 利益 2,900円
   資金回転       : 10日サイクル → 月あたり約 8,700円

3. 海外EC（安いが遅い）  [スコア 69/100]
   単価 / 実質原価: 2,800円 / 3,580円（送料按分・不良率込み）
   1個あたり利益  : 4,520円（利益率 45.2% / ROI 126.3%）
   資金回転       : 37日サイクル → 月あたり約 32,250円
   最低ロット 10 個。1回の発注で 31,500 円を寝かせることになります。
   ロット 10 個のうち 4 個売れた時点で発注額を回収できます。
   リードタイムが 28 日と長く、到着時に相場が下がっている可能性があります。
   不良率 12%。検品の手間と返品リスクを見込んでください。
   取引実績が3回未満です。まずは最小ロットで試すことを勧めます。
```

**「単価が一番安い仕入れ先」を推しません。** 評価に入れているもの:

| 要素 | 配点 | 理由 |
|---|---|---|
| ROI | 35 | 資金効率。同じ金額で何回転できるか |
| 利益率 | 20 | 1個あたりの厚み |
| リードタイム | 15 | 到着が遅いほど相場変動リスクを負う |
| 信頼度 | 15 | 取引実績が浅い相手は上限を抑える |
| 不良率 | 10 | 実質原価が上がり、返品対応の手間も増える |
| 最低ロット | 5 | 在庫リスクと資金拘束 |

不良率と発注送料は**実質原価に織り込んで**計算します（例: 単価2,800円でも
送料按分＋不良率12%込みで実質3,580円）。

#### 純利益と現金収支を分けている理由

ご依頼の「仕入れ金額と売上の差引」は、実は**2通りの意味**があります。
どちらか一方だけだと判断を誤るので、両方出しています。

| 指標 | 計算 | 何が分かるか |
|---|---|---|
| **純利益** | 売上 −（**売れた商品の**仕入値 + 手数料 + 送料 + 梱包費） | 商売として儲かっているか |
| **現金収支** | 売上 −（手数料 + 送料 + 梱包費）− **その期間に支払った**仕入額 | 手元のお金が増えているか |

上の例の2026年8月は、**純利益 +3,659円なのに現金収支 −10,808円**です。
これは仕入れを18,800円ぶん増やしたためで、赤字ではありません。
純利益だけ見ていると在庫過多に気づけず、現金収支だけ見ていると
「仕入れた月は必ず赤字」に見えてしまいます。

#### Googleスプレッドシートへの反映

```bash
python -m mercari_tool sales sync
# 記録と同時に反映することもできます
python -m mercari_tool sales add --sku NK-AM90-27 --price 11180 --sync
```

以下のシートが自動で作られ、毎回上書きされます。

| シート | 内容 |
|---|---|
| サマリー | 全期間・直近月の売上／純利益／仕入との差引 |
| 日次推移 | 日ごとの売上・原価・手数料・純利益・仕入額・現金収支 |
| 月次推移 | 月ごとの同上 |
| 売上明細 | 1件ずつの内訳（売却日・日数・各費用・純利益・利益率） |
| 仕入明細 | 1件ずつの仕入（単価・数量・送料・実質単価） |
| カテゴリ別 | カテゴリごとの売上・利益率・ROI・平均売却日数 |
| 在庫 | 未販売の商品と、そこに寝ている金額 |

金額は `¥#,##0`、利益率は `0.0%` で書式設定され、ヘッダー行は固定されます。

**セットアップ**:

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. **Google Sheets API** と **Google Drive API** を有効化
3. サービスアカウントを作成し、JSONキーをダウンロード
4. `.env` に `GOOGLE_SERVICE_ACCOUNT_JSON=./credentials/service-account.json`
5. 既存のスプレッドシートを使う場合、**サービスアカウントのメールアドレスに
   編集権限を共有**し、`GOOGLE_SPREADSHEET_KEY` にURLの `/d/` と `/edit` の間の
   文字列を設定（未設定なら新規作成されます）

台帳（`data/*.json`）が唯一の正で、シートは毎回作り直します。
シート側で手編集しても次回同期で消えるので、修正は台帳側に対して行ってください。


- **日本語のヘッダーをそのまま使えます**（`商品名` `仕入値` `配送方法` …）。列の順番は自由、

- **既に登録済みのSKUは「更新」**です。CSVに無い列（前に入れたキーワードなど）は
  空欄扱いで消されません。在庫だけ書いたCSVで在庫の更新ができます。
- 配送区分が不正な行、SKUが空の行は取り込まず、理由を表示します。
